# 原车状态条件分析（2026-10-03）

## 已修复：露营状态

实车开启露营时 `zeekr_bs_camp_mode=3`，退出后为 `0`。两次 `zeekr_bs_camp_mode_enable` 都为 `0`，不能用它判定是否开启。

原车设置的车门观察器同样读取 `zeekr_bs_camp_mode`，以 3 / 0 控制接近开门选项。v3.43 改用该字段：3 开启、0 关闭，其它值或读取失败为未知。已有规则无需重建。单元测试不代替实车验证。

## 研究来源和边界

只读提取本车智慧场景编辑器及场景引擎，分析其状态读取接口。编辑器明确区分“触发条件”和“状态条件”；本应用当前扩展的是执行前的状态判断，不是持续运行的场景自动化引擎。

反编译有部分错误，嵌套条件资源无法完整读取。因此以下是接口候选，不是已验证可用的功能目录。不引入整套原车 APK 或复制其专有 SDK、密钥及许可证。

## 接入设计

- 分类选择状态；枚举提供“是/不是”，数值提供“低于/高于/等于”，标明单位。
- 同一规则支持满足全部（AND）或任一（OR），以及允许/禁止。
- 规则限定设备和动作；例如露营时仅禁止四门动作，不影响音量。
- 读取失败、不可用或过期值显示“未知”；受规则保护的动作继续保守拦截。
- UI 展示当前值及读取状态，试算不实际执行车辆动作。
- 首批候选：车速、电量、车门、座椅占用、车外温度。安全带和其它场景待接口核实后再加。

新增目录原型为设计演示，不读取车辆，不执行动作，未接入 Android。
